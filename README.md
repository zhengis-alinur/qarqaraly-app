# Qarqaraly — туристический портал Каркаралинска

Локальный MVP на Next.js App Router, TypeScript и MongoDB. Русский интерфейс, адаптивная вёрстка для телефонов, планшетов и компьютеров.

## Возможности

- Главная, каталог, поиск по названию, категории, диапазон цен, удобства, сортировка и пагинация. Фильтры сохраняются в URL. Неуказанная цена не считается нулевой и идёт в конце сортировки по цене.
- Leaflet-карта с теми же фильтрами, карточками маркеров и доступным текстовым списком объектов. Объекты без координат остаются в каталоге.
- Страница объекта: галерея, условия, контакты, карта, дата подтверждения, сообщение о неточности. Прямые переходы к телефону, WhatsApp и маршруту.
- Регистрация и вход только по номеру телефона. Пароли хешируются bcrypt, сессия хранится в HTTP-only cookie. Сброс пароля отзывает прежние сессии. Выход — в попапе кнопки «Профиль» в шапке. Вход по email оставлен служебным путём `/auth/login?email=1` для администратора; публичных форм с почтой и писем нет.
- Номер телефона Казахстана: код из шести цифр в SMS через Mobizon, подтверждение номера, вход по коду или по номеру и паролю, восстановление пароля по SMS. Код хранится только в виде HMAC, действует пять минут, повторная отправка не чаще раза в минуту, пять кодов в час на номер и пятнадцать на IP, пять попыток ввода. Страницы: `/auth/register`, `/auth/login`, `/auth/forgot`.
- Кабинет бизнеса: несколько объектов, черновики, фотографии, обложка, координаты, отправка на модерацию, исправления, снятие с публикации и подтверждение актуальности.
- Раздельные предложенная и опубликованная версии: редактирование не меняет публичные сведения до одобрения. Согласованные изменения сохраняются в истории редакций. Проверка версии предотвращает перезапись конкурентных изменений.
- Админка: поиск, модерация, редактирование и скрытие объектов, назначение владельца после проверки, категории, удобства, статьи и сообщения о неточностях.
- Статистика по каждому объекту и за выбранный период: просмотры, телефон, WhatsApp, маршрут. Повторы одного браузера ограничены часовым интервалом. Это события интереса, не бронирования.
- Напоминания об актуальности через 30 дней, публичное предупреждение через 60 дней. Интервалы настраиваются в окружении; сохранение текста не подтверждает актуальность.
- SSR публичных страниц, metadata, canonical, robots.txt, sitemap.xml. Кабинет, админка и страницы авторизации исключены из индексации.

Каталог и статьи изначально пусты. Справочники категорий и удобств создаются автоматически. Демонстрационные объекты не загружаются автоматически.

## Локальная разработка

Требуются Node.js 24+ и Docker с Compose.

```sh
cp .env.example .env
# В .env замените SESSION_SECRET, например результатом openssl rand -hex 32.
npm ci
docker compose -f compose.yaml -f compose.local.yaml up -d mongo mail
npm run dev
```

Если `.env` уже создан в ходе локальной установки, не заменяйте его без необходимости. Сайт: **http://localhost:3000**. Писем приложение не отправляет: подтверждение номера и восстановление пароля идут по SMS, а без `MOBIZON_API_KEY` код виден в консоли `npm run dev`.

В режиме разработки MongoDB открыта только на loopback компьютера. Если порт 27017 занят, измените `compose.local.yaml` и `MONGODB_URI` в `.env`.

### Открыть сайт с телефона в одной Wi-Fi сети

1. Узнайте локальный IP компьютера в настройках сети.
2. Установите в `.env` `APP_URL=http://ВАШ_ЛОКАЛЬНЫЙ_IP:3000` и перезапустите `npm run dev`.
3. Откройте этот же URL на телефоне. Разрешите входящие подключения Node.js в системном брандмауэре, если потребуется.

`APP_URL` должен совпадать с адресом сайта в браузере: он используется для проверки Origin при отправке форм и ссылок в письмах. Не используйте разные адреса для одного сеанса. Для публичного HTTPS-домена cookie автоматически получает флаг Secure.

## Первый администратор

Для локального npm-запуска:

```sh
ADMIN_EMAIL=admin@example.com npm run admin:create
```

Скрипт запросит пароль (12–72 символа). Интерактивный ввод виден в терминале. Для автоматизации можно передать `ADMIN_PASSWORD` через окружение, не добавляя его в репозиторий. Скрипт не изменяет роль уже существующего пользователя.

Вход: `/auth/login`, панель: `/admin`. Администратор также может создавать собственные объекты в `/dashboard`. Преднастроенных общих паролей в проекте нет.

## Оплата размещения: статический QR Halyk

Оплата сознательно сделана без платёжного шлюза. На странице `/dashboard/pay` показывается статический
QR Halyk: плательщик сканирует его приложением банка и **вводит сумму вручную**. Подтверждение на сайт
не приходит, поступление администратор сверяет по выписке.

Порядок такой: владелец регистрируется по номеру телефона, заполняет объект и отправляет на проверку —
заявка уходит в модерацию сразу, оплату она не ждёт. Администратору приходит уведомление в Telegram.
Объект публикуется, когда администратор нажимает «Одобрить» в `/admin`. Пока объект на проверке, в
кабинете висит напоминание об оплате со ссылкой на страницу с кодом; в комментарии к платежу
предлагается указать первые восемь символов номера заявки, чтобы её проще было найти в выписке.

| Переменная | Назначение |
| --- | --- |
| `PAYMENT_QR` | Путь к файлу QR от корня сайта, по умолчанию `/pay/halyk-qr.png`. Файл кладётся в `public/pay/`. Пока файла нет, блок оплаты не показывается. |
| `PAYMENT_AMOUNT` | Сумма в тенге для показа на странице. Пусто — сумма не показывается. |
| `PAYMENT_LINK` | Необязательная ссылка на оплату для кнопки «Открыть в приложении банка». |
| `PAYMENT_NOTE` | Необязательная дополнительная строка на странице оплаты. |
| `TELEGRAM_BOT_TOKEN` | Токен бота от `@BotFather`. Бот нужен отдельный, не общий с другими проектами. |
| `TELEGRAM_CHAT_ID` | Куда писать: ваш личный chat id или id группы. |

Оба ключа Telegram необязательны: если они пустые, уведомление молча пропускается. Сбой отправки
не отменяет заявку — она всё равно уходит в модерацию, а ошибка попадает в лог сервера.

## Регистрация по телефону: SMS через Mobizon

Коды подтверждения отправляет [Mobizon](https://mobizon.kz) — казахстанский шлюз с прямыми подключениями к операторам. Переменные окружения:

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `MOBIZON_API_KEY` | да для production | Ключ API из личного кабинета Mobizon: «Настройки» → «API». Без ключа в разработке код печатается в консоль сервера, в production отправка отклоняется с явной ошибкой. |
| `MOBIZON_SENDER` | нет | Согласованное буквенное имя отправителя (альфанейм). Пусто — используется имя по умолчанию в аккаунте. |
| `MOBIZON_API_URL` | нет | По умолчанию `https://api.mobizon.kz`. |
| `PHONE_OTP_SECRET` | нет | Отдельный ключ (минимум 32 символа) для HMAC кодов и подписи токенов подтверждения. Пусто — используется `SESSION_SECRET`. |
| `PHONE_OTP_TEST_NUMBERS` | нет | Номера для приёмки без расхода SMS: `+77010000001:123456,+77010000002:654321`. Для таких номеров код фиксирован и лимиты не применяются. Не оставляйте в production. |

Поток: `POST /api/auth/phone/send-code` с номером и целью (`signup`, `login`, `reset`) → `POST /api/auth/phone/verify-code` возвращает токен подтверждения на десять минут → `POST /api/auth/phone-register`, `/api/auth/phone-login` или `/api/auth/phone-reset` с этим токеном. Вход без SMS: `POST /api/auth/phone/password` с номером и паролем. Номер приводится к формату E.164 `+77XXXXXXXXX`, принимается запись через 8, пробелы и скобки.

Пригодность номера проверяется до отправки: для регистрации номер должен быть свободен, для входа и восстановления — зарегистрирован. Так не оплачивается SMS для запроса, который следующий шаг всё равно отклонит. Сбой шлюза не расходует часовой лимит номера. Коллекция `otps` одновременно служит журналом лимитов и очищается через сутки индексом TTL.

Номер подтверждён кодом при регистрации, поэтому такой аккаунт сразу может отправлять объекты на модерацию. Индексы `users` по email и телефону частичные: у аккаунта есть либо почта (создан скриптом администратора), либо номер. Прежний непартиальный индекс `email_1` снимается автоматически при первом обращении к базе. В админке владелец назначается по email или по номеру телефона.

## Docker Compose: production-сборка

1. Создайте `.env` из `.env.example`.
2. Укажите реальный `APP_URL`, случайный `SESSION_SECRET` и `MOBIZON_API_KEY`.
3. Запустите:

```sh
docker compose up -d --build
```

MongoDB доступна только внутри Docker-сети. Есть healthcheck приложения и MongoDB, постоянные тома `mongodb` и `uploads`. Приложение работает от непривилегированного пользователя. Для внешнего доступа настройте HTTPS на обратном прокси; Compose сам TLS не выпускает.

Первый администратор в Docker:

```sh
docker compose --profile tools run --rm --build -e ADMIN_EMAIL=admin@example.com tools scripts/create-admin.ts
```

При работе через доверенный reverse proxy можно установить `TRUST_PROXY=true` только если прокси перезаписывает заголовок `X-Forwarded-For`. По умолчанию лимит запросов без доверенного IP общий, плюс отдельные ограничения для email и аккаунтов.

Источник тайлов задаётся `NEXT_PUBLIC_TILE_URL`, атрибуция — `NEXT_PUBLIC_TILE_ATTRIBUTION`. По умолчанию используется OpenStreetMap. Эти публичные переменные считываются при сборке Next.js; при смене источника для Docker измените `.env` и пересоберите образ (Compose передаёт эти значения как build arguments). Соблюдайте условия выбранного провайдера тайлов.

## Демонстрационные данные — только по явной команде

```sh
ALLOW_DEMO_SEED=true npm run seed:demo
```

В Docker:

```sh
docker compose --profile tools run --rm --build -e ALLOW_DEMO_SEED=true tools scripts/seed.ts
```

Команда идемпотентно добавляет 24 объекта с `ДЕМО` в названии и пометкой на странице: магазины, развлечения, зоны отдыха, прокат квадроциклов, велосипедов и коней, точки продажи кымыза, достопримечательности и городские службы, а также гостевой дом и кафе. У них нет вымышленных цен, контактов или отметок подтверждения. Координаты — условная сетка для демонстрации карты; построение маршрута для демо-объектов отключено. При повторном запуске тексты и существующие фотографии сохраняются. Пустые галереи опубликованных демо-карточек без владельца дополняются иллюстративными фото. Они не привязаны к реальному владельцу. При необходимости администратор может назначить владельца или снять объекты с публикации. Не добавляйте демо-данные в рабочую базу.

## Резервное копирование

Выполняйте команды из корня проекта. Копии базы и фотографий должны соответствовать одному моменту: на время копирования остановите входящие записи (например, включите режим обслуживания на прокси).

```sh
mkdir -p backups
docker compose exec -T mongo mongodump --db qarqaraly --archive --gzip > backups/database.archive.gz
docker compose exec -T app tar czf - -C /app/uploads . > backups/uploads.tar.gz
```

Храните резервные копии вне сервера с ограниченным доступом: база содержит приватные сведения пользователей и хеши паролей. Отдельно сохраните конфигурацию окружения в защищённом хранилище.

### Восстановление

Следующие команды **заменяют существующие коллекции** резервной копией; выполняйте их осознанно на целевом окружении, остановив запись в приложение.

```sh
docker compose up -d mongo
docker compose exec -T mongo mongorestore --archive --gzip --drop < backups/database.archive.gz
# Приложение должно быть запущено для exec; заблокируйте внешние запросы на прокси.
docker compose up -d app
docker compose exec -T app tar xzf - -C /app/uploads < backups/uploads.tar.gz
```

`docker compose down` сохраняет данные. `docker compose down -v` удаляет тома — не используйте его для обычного перезапуска.

## Команды и ручная приёмка

```sh
npm run dev        # локальный сервер, доступный по сети
npm run typecheck  # проверка TypeScript
npm run build      # production-сборка
npm start          # запуск production-сборки вне Docker
```

Рекомендуемые пользовательские сценарии для самостоятельной проверки:

1. Зарегистрируйтесь по номеру телефона: без `MOBIZON_API_KEY` код виден в консоли `npm run dev`. Проверьте повторную отправку, неверный код и вход по номеру с паролем.
1. Откройте попап кнопки «Профиль» в шапке и выйдите из аккаунта.
1. Отправьте объект на проверку: должно прийти уведомление в Telegram, а в кабинете появиться напоминание об оплате со страницей QR.
2. Создайте объект с фотографиями и координатами, сохраните черновик и отправьте на модерацию.
3. В отдельном браузере войдите администратором и опубликуйте объект.
4. Проверьте каталог, фильтры, карту, страницу объекта и переходы к контактам на телефоне.
5. Измените опубликованную карточку: до одобрения должна отображаться прежняя версия.
6. Создайте второго представителя и убедитесь, что чужие объекты недоступны ему для редактирования.
7. Подтвердите актуальность, отправьте сообщение о неточности, посмотрите статистику.
8. Восстановите пароль по письму; прежние сессии должны завершиться.
9. Пересоздайте контейнеры без удаления томов: карточки и фото должны сохраниться.

По просьбе заказчика итоговая сборка, браузерная проверка и полный набор сценариев приёмки не запускались. До этой просьбы была выполнена одна проверка TypeScript; обнаруженный отсутствующий импорт исправлен, повторная проверка не проводилась.

## Структура

- `src/app` — страницы, metadata и обработчики API.
- `src/components` — адаптивные компоненты, формы и интерактивная карта.
- `src/lib` — типы, MongoDB, авторизация, валидация и запросы каталога.
- `scripts` — создание администратора и явное добавление демо-данных.
- `uploads` / Docker-том — оптимизированные изображения WebP.

Загруженные фотографии проверяются по формату и содержимому, ограничены 10 МБ и 40 мегапикселями, уменьшаются до 1800 px, преобразуются в WebP без исходных метаданных. До 10 фотографий на карточку. Первая фотография — обложка; остальные можно снабдить подписями. Неиспользуемые загрузки автоматически не удаляются.

На главной используется реальная фотография леса Каркаралинского национального парка (Rauka04, Wikimedia Commons, CC BY-SA 4.0); атрибуция размещена под главным баннером. Схема в блоке карты обозначена как иллюстрация. Шрифт Manrope имеет системный fallback; загрузка внешнего шрифта не блокирует интерфейс.

## Перед публичным запуском

Укажите рабочий `MOBIZON_API_KEY` с согласованным альфанеймом, домен, реквизиты оператора и контакт для обращений в политике конфиденциальности. Наполните каталог проверенными объектами, а путеводитель — статьями с источником и датой проверки. Свободные места, бронирования, оплата, отзывы, чат и интеграции с CRM в этот MVP не входят.

## Фотографии демо-карточек

В `scripts/assets/demo` сохранены 12 иллюстративных фотографий Unsplash в WebP. Это изображения для оформления макета, не фотографии объектов Каркаралинска. Молочная продукция показана как общая иллюстрация, а не как реальный кымыз продавца. На страницах выводятся подписи. Некоторые тематические фото используются в нескольких карточках.

`npm run seed:demo` (с `ALLOW_DEMO_SEED=true`) копирует готовые локальные файлы в хранилище загрузок и добавляет обложки / галереи демо-карточкам. Интернет для этой операции не нужен. Пользовательские фотографии не заменяются. Источники и подписи перечислены в `scripts/photo-sources.json` и сохраняются в метаданных фотографий MongoDB.

Для повторного скачивания исходных иллюстраций: `node --import tsx scripts/download-demo-photos.ts`. Источник: [Unsplash](https://unsplash.com), условия: [Unsplash License](https://unsplash.com/license).

## Редакционный контент: 30 статей, достопримечательности и новости

- `/guide` — 30 оригинальных русскоязычных материалов: 12 о достопримечательностях, 4 плана прогулок/поездок и 14 практических статей. Разделы показаны в этом порядке; работают поиск и фильтрация по разделу.
- `/sights` — отдельная подборка настоящих достопримечательностей с фильтрами «В городе», «Национальный парк», «Кентские горы». Она не использует вымышленные карточки каталога.
- `/news` — 4 редакционных пересказа открытых публикаций. На момент наполнения самые новые сообщения датированы 19 и 16 сентября 2026 года; также включены полезные сообщения июля и июня. Даты источников показаны явно. Это подборка, а не автоматически обновляющаяся новостная лента.
- `/guide/[slug]`, `/news/[slug]` — отдельные адреса, уникальные title/description, canonical, Open Graph, Article/NewsArticle и BreadcrumbList в JSON-LD, оглавление и связанные материалы.

Факты о местах опираются на Visit Karaganda, государственные публикации и Институт археологии. Практические рекомендации составлены редакционно; они не скопированы из чужих статей и не выдаются за официальный маршрут. Спорные расстояния, непроверенные текущие цены и неподтверждённые режимы работы не публикуются как достоверные сведения. Время на месте, доступность маршрутов и тарифы необходимо согласовывать для конкретной поездки.

Источники просмотрены **30 сентября 2026 года**. Дата фиксированная: она не обновляется автоматически при рендеринге, повторном импорте или обычном изменении текста. Даты новостных источников хранятся отдельно от даты публикации пересказа на портале.

### Повторное развёртывание материалов

```sh
npm run seed:editorial
```

В Docker:

```sh
docker compose --profile tools run --rm --build tools scripts/seed-editorial.ts
```

Скрипт добавляет отсутствующие публикации по уникальному slug, копирует локальные WebP в постоянное хранилище и сохраняет атрибуцию фотографий. Уже существующие материалы не перезаписываются. Обновлять их можно в `/admin?tab=articles`: доступны тип «Статья/Новость», раздел, текст, источники и даты. Подзаголовки в тексте обозначаются `## `, абзацы разделяются пустыми строками. Произвольный HTML не исполняется.

Исходные тексты: `content/articles.json`, `content/news.json`. Реестр источников: `content/source-register.json`. Импортированные новости не входят в счётчик 30 статей путеводителя.

### Реальные фотографии Каркаралинска

10 фотографий из Wikimedia Commons сохранены в `scripts/assets/editorial`. Они показывают Каркаралинск, Шайтанколь, Бассейн, Самал, мечеть Кунанбая, Дом лесника, лес национального парка, Кентские горы и руины Кызылкентского дворца. Есть зимний снимок города. Лицензии CC BY-SA 3.0 / 4.0 сохранены: на страницах указаны автор, источник, лицензия и изменения (масштабирование, WebP, кадрирование при показе). Лицензия производных изображений остаётся соответствующей CC BY-SA; это не изменяет лицензию программного кода.

Манифест: `content/editorial-photos.json`. Первичные описания файлов и лицензий сохранены в `content/commons-*.json`. Повторное получение: `node --import tsx scripts/download-editorial-photos.ts` (уже скачанные позиции из манифеста пропускаются). Для обычного импорта статей интернет не нужен.

Там, где нет отдельного снимка объекта (например, интерьера музея), обложкой служит подписанная панорама Каркаралинска или природный вид региона. Такие снимки не выдаются за фотографии конкретного здания или новостного события.

Демонстрационные объекты исключены из sitemap и помечены noindex на своих страницах. Полезные редакционные материалы и настоящие достопримечательности доступны для индексации после публикации сайта на публичном домене. SEO-разметка не гарантирует позиции в поиске; сайт, работающий только на localhost, поисковикам недоступен.
